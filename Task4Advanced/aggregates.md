# Агрегаты и границы DDD — «Будущее 2.0»

**Цель:** независимая бизнес-логика в bounded contexts, без общих операционных таблиц и бизнес-правил внутри DWH. Каждый контекст владеет своими данными; взаимодействие между контекстами — через события Kafka, а запрос/команда к ИИ при необходимости через защищённый API.

| Домен / bounded context | Корневой агрегат (Aggregate Root) | Ключ | Основные инварианты | Публикуемые события |
|---|---|---|---|---|
| Клиники / **Patient Registry** | `Patient` | `patient_id` | Пациент не регистрируется дважды по проверенному идентификатору; изменение персональных данных контролируется реестром | `PatientRegistered` |
| Клиники / **Clinical Care** | `Encounter` (приём) | `encounter_id` | Приём относится к существующему пациенту; завершённый приём не меняется без отдельного исправления; медицинские данные доступны только уполномоченным ролям | `EncounterCompleted`, `MedicationOrderPlaced`, `ClinicalVisitsAggregated` |
| Клиники / **Billing** | `Invoice` (счёт) | `invoice_id` | Сумма счёта равна сумме позиций; нельзя оплатить/закрыть несуществующий счёт; повторная обработка платежа не удваивает сумму | `InvoiceIssued` |
| Клиники / **Inventory** | `StockItem` (остаток) | `stock_item_id` | Остатки учитываются по товару и месту хранения; списание не уводит остаток в минус без разрешённого механизма резервирования | `StockBelowThreshold` |
| ИИ / **AI Diagnostics** | `AIAnalysis` | `analysis_id` | Одно исследование имеет однозначный жизненный цикл; событие о завершении публикуется после фиксации результата; сами снимки и заключения остаются в защищённом контуре | `AIStudyCompleted`, `AIUsageAggregated` |
| Финтех / **Lending** | `CreditContract` | `contract_id` | Договор создаётся только после проверки условий и согласия; сумма и сроки зафиксированы при активации | `CreditContractCreated` |
| Финтех / **Payments** | `Payment` | `payment_id` | Внешний `transaction_id` обрабатывается идемпотентно; статус оплаты меняется только по разрешённым переходам | `PaymentReceived` |
| Новое направление / **Pharmacy Orders** | `PharmacyOrder` | `pharmacy_order_id` | Заказ имеет допустимого получателя и согласованный состав; создание заказа не дублируется при повторной доставке события | `PharmacyOrderCreated` |
| Новое направление / **Medical Devices** | `DeviceSession` | `session_id` | Показания связаны с корректным устройством и сессией; сырые медицинские данные не публикуются в общий поток | `DeviceTelemetryReceived` |
| Головной офис / **Analytics & Reporting** | `ReportJob` (запрос отчёта) | `report_job_id` | Отчёт строится только по разрешённым срезам и правам пользователя; не содержит медкарты, снимки и результаты исследований | Нет обязательных междоменных событий; потребляет безопасные проекции |
