# Расширенный технологический радар «Будущее 2.0»
## Значение статусов

## 1. Архитектурные подходы и паттерны

| Технология / паттерн | Статус | Для чего нужен |
|---|---|---|
| Domain-Driven Design (bounded contexts) | **Adopt** | Разделение медицинского, финансового, ИИ и новых доменов по ответственности. |
| Event-Driven Architecture | **Adopt** | Асинхронная интеграция и независимое развитие доменов. |
| Transactional Outbox | **Adopt** | Надёжная публикация событий вместе с изменением бизнес-данных. |
| Schema Registry + версионирование контрактов | **Adopt** | Совместимость производителей и потребителей событий. |
| Retry + Dead Letter Queue (DLQ) | **Adopt** | Контролируемая обработка временных и неисправимых ошибок. |
| Privacy by Design / минимизация данных | **Adopt** | Не допускать медицинские карты, снимки и истории болезни в аналитический контур. |
| Data Mesh / доменные data products | **Trial** | Проверить владение данными доменами на 1–2 пилотных продуктах. |
| Self-service BI | **Trial** | Пилот самостоятельного создания отчётов сотрудниками с правами доступа. |
| Change Data Capture (CDC) | **Trial** | Временная доставка изменений из легаси в ходе миграции. |
| Saga | **Assess** | Для распределённых бизнес-процессов, если они появятся. |
| CQRS | **Assess** | Для доменов с заметно разными нагрузками чтения и записи. |
| Event Sourcing | **Hold** | Не внедрять повсеместно: сложность и стоимость не обоснованы. |

## 2. Платформа данных и инструменты

| Технология | Статус | Целевая роль |
|---|---|---|
| Apache Kafka | **Adopt** | Событийная шина между доменами. |
| PostgreSQL | **Adopt** | Операционные базы отдельных доменных сервисов (где подходит). |
| Объектное хранилище S3-совместимого типа | **Adopt** | Масштабируемое хранилище разрешённых аналитических данных. |
| Apache Iceberg | **Adopt** | Формат аналитических таблиц Lakehouse. |
| Trino | **Adopt** | SQL-доступ к Lakehouse для BI и Report API. |
| Power BI | **Adopt** | Сохранить как BI-интерфейс, исключив прямую зависимость от легаси DWH. |
| Apache Flink | **Trial** | Потоковые преобразования и near-real-time витрины. |
| Debezium | **Trial** | CDC-мост с SQL Server и другими источниками на этапе миграции, после проверки поддержки версий. |
| Apache Airflow | **Assess** | Оркестрация оставшихся пакетных загрузок и перерасчётов. |
| Data Catalog (например, OpenMetadata) | **Trial** | Описание data products, владельцев, качества и схем. |
| Управляемый Kubernetes | **Assess** | Развёртывание сервисов, если оправдано эксплуатационными затратами. |

## 3. Безопасность и старые решения

| Технология / практика | Статус | Причина |
|---|---|---|
| IAM / RBAC / аудит доступа | **Adopt** | Разграничение доступа к отчётам и данным разных бизнес-доменов. |
| Data Classification + Privacy Filter | **Adopt** | Классификация, маскирование и запрет загрузки медицинских исследований в Lakehouse. |
| Keycloak (как вариант IAM) | **Trial** | Проверить интеграцию с корпоративной идентификацией и BI. |
| SQL Server 2008 как центральный DWH | **Hold** | Заморозить развитие, переносить аналитические функции и бизнес-логику. |
| Apache Camel ESB | **Hold** | Только временный мост совместимости; новые интеграции делать через события/API. |
| PowerBuilder | **Hold** | Постепенно заменить интерфейсами доменных приложений. |
